# Palm Mind RAG API

A FastAPI backend with two REST APIs:

1. **Document Ingestion API**: upload `.pdf` or `.txt` files, extract text, split it with one of two selectable chunking strategies, embed the chunks, store the vectors in **Qdrant**, and save document metadata in an **SQL database**.
2. **Conversational RAG API**: a custom retrieval-augmented generation pipeline (no `RetrievalQAChain`, no LangChain) with **Redis** chat memory, multi-turn handling, and **LLM-driven interview booking** that stores bookings in SQL.

The whole stack runs on free tiers: Qdrant Cloud, Redis Cloud, Groq, and local embeddings.

---

## Features

- Upload `.pdf` and `.txt` files (10 MB limit by default).
- Two chunking strategies, selectable per upload: `fixed` and `sentence`.
- Local sentence-transformer embeddings (384 dimensions, cosine similarity).
- Vectors and chunk text stored in Qdrant; document metadata stored in SQL.
- Custom RAG pipeline: follow-up rewriting, retrieval, grounded answer generation, and source citations in the response.
- Multi-turn conversations with per-session history in Redis (trimmed, with a TTL).
- Interview booking through natural language: the LLM extracts name, email, date and time across several turns, code validates them, and the booking is saved to SQL.
- Fully typed code (`mypy --strict`), linted with ruff, and covered by tests that need no network access.

## Tech stack

| Concern         | Choice                                                             |
| --------------- | ------------------------------------------------------------------ |
| Web framework   | FastAPI + Uvicorn                                                  |
| Vector database | Qdrant (Qdrant Cloud free tier)                                    |
| SQL database    | SQLite through SQLAlchemy 2.0 (change `DATABASE_URL` for Postgres) |
| Chat memory     | Redis (Upstash or Redis Cloud free tier)                           |
| Embeddings      | `sentence-transformers/all-MiniLM-L6-v2` (local)                   |
| LLM             | Groq `llama-3.3-70b-versatile` through its OpenAI-compatible API   |
| PDF parsing     | pypdf                                                              |
| Tests           | pytest, fakeredis, fake LLM and vector store                       |

Not used, by design: FAISS, Chroma, LangChain's `RetrievalQAChain`, and any UI. Swagger UI at `/docs` is generated by FastAPI and is not a custom interface.

## Getting started

### Prerequisites

- Python 3.11 or newer
- A free [Groq API key](https://console.groq.com)
- Qdrant and Redis, using **either** option below

### 1. Clone and install

**macOS / Linux**

```bash
git clone https://github.com/<your-username>/palmmind-rag.git
cd palmmind-rag
python -m venv .venv
source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

**Windows (PowerShell)**

```powershell
git clone https://github.com/<your-username>/palmmind-rag.git
cd palmmind-rag
python -m venv .venv
.venv\Scripts\activate
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

Installing the CPU build of PyTorch first keeps the download small. Skip that line if you already have PyTorch.

### 2. Provide Qdrant and Redis

**Option A: free cloud tiers (no Docker)**

1. Create a free cluster at [cloud.qdrant.io](https://cloud.qdrant.io). Copy the cluster URL (with `:6333`) and create an API key.
2. Create a free Redis database at [Upstash](https://upstash.com) or [Redis Cloud](https://redis.io/cloud). Build the connection URL:
   - TLS (Upstash): `rediss://default:<PASSWORD>@<ENDPOINT>:6379`
   - Non-TLS: `redis://default:<PASSWORD>@<HOST>:<PORT>`
3. URL-encode special characters in the password (for example `@` becomes `%40`).

**Option B: Docker**

```bash
docker compose up -d
```

This starts Qdrant on port 6333 and Redis on port 6379, matching the defaults in `.env.example`.

### 3. Configure the environment

```bash
cp .env.example .env        # Windows: copy .env.example .env
```

Edit `.env` (see [Configuration](#configuration)). At minimum set `GROQ_API_KEY`, and for cloud services set `QDRANT_URL`, `QDRANT_API_KEY` and `REDIS_URL`.

### 4. Verify the connections (optional but recommended)

```bash
python -m scripts.check_connections
```

Expected output:

```
Qdrant OK, collections: []
Redis OK: ok
```

### 5. Run the server

```bash
uvicorn app.main:app --reload
```

On startup the app creates the SQL tables and the Qdrant collection if they do not exist. Open **http://localhost:8000/docs** for the interactive Swagger documentation. The first document upload downloads the embedding model (about 90 MB) once.

## Configuration

All settings are read from environment variables or `.env`.

| Variable             | Default                                  | Description                                              |
| -------------------- | ---------------------------------------- | -------------------------------------------------------- |
| `GROQ_API_KEY`       | (required)                               | API key for the LLM provider                             |
| `GROQ_MODEL`         | `llama-3.3-70b-versatile`                | Chat model name                                          |
| `GROQ_BASE_URL`      | `https://api.groq.com/openai/v1`         | Any OpenAI-compatible endpoint works                     |
| `QDRANT_URL`         | `http://localhost:6333`                  | Qdrant endpoint                                          |
| `QDRANT_API_KEY`     | empty                                    | Required for Qdrant Cloud                                |
| `QDRANT_COLLECTION`  | `documents`                              | Collection name                                          |
| `REDIS_URL`          | `redis://localhost:6379/0`               | Use `rediss://` for TLS                                  |
| `DATABASE_URL`       | `sqlite:///./data/app.db`                | Any SQLAlchemy URL, for example Postgres                 |
| `EMBEDDING_MODEL`    | `sentence-transformers/all-MiniLM-L6-v2` | Embedding model                                          |
| `EMBEDDING_DIM`      | `384`                                    | Must match the model; recreate the collection if changed |
| `TOP_K`              | `4`                                      | Chunks retrieved per question                            |
| `CHAT_HISTORY_TURNS` | `6`                                      | Turns of history kept per session                        |
| `CHAT_TTL_SECONDS`   | `3600`                                   | Session expiry in Redis                                  |
| `MAX_UPLOAD_MB`      | `10`                                     | Upload size limit                                        |

## API reference

Base path: `/api/v1`. Interactive docs: `/docs` (Swagger) and `/redoc`.

| Method | Path                | Purpose                                   |
| ------ | ------------------- | ----------------------------------------- |
| `POST` | `/api/v1/documents` | Upload and ingest a `.pdf` or `.txt` file |
| `GET`  | `/api/v1/documents` | List ingested documents (newest first)    |
| `POST` | `/api/v1/chat`      | Conversational RAG and interview booking  |
| `GET`  | `/api/v1/bookings`  | List stored interview bookings            |
| `GET`  | `/health`           | Liveness check                            |

### `POST /api/v1/documents`

Multipart form fields:

| Field           | Type                  | Default  | Notes                                    |
| --------------- | --------------------- | -------- | ---------------------------------------- |
| `file`          | file                  | required | `.pdf` or `.txt`                         |
| `strategy`      | `fixed` or `sentence` | `fixed`  | Chunking strategy                        |
| `chunk_size`    | integer               | `800`    | 100 to 4000 characters                   |
| `chunk_overlap` | integer               | `100`    | At least 0 and smaller than `chunk_size` |

```bash
curl -F "file=@sample.pdf" -F "strategy=sentence" -F "chunk_size=800" -F "chunk_overlap=100" \
     http://localhost:8000/api/v1/documents
```

On Windows PowerShell use `curl.exe` instead of `curl`.

Response (`201`):

```json
{
  "id": "bc6138c6-f43b-458b-bfcc-e6231de343ce",
  "filename": "hr_rag_demo_documents.pdf",
  "content_type": "application/pdf",
  "size_bytes": 36367,
  "chunking_strategy": "fixed",
  "chunk_size": 800,
  "chunk_overlap": 100,
  "num_chunks": 12,
  "created_at": "2026-11-13T17:22:45.311543"
}
```

Errors: `400` (unsupported type, empty or unreadable file, invalid chunk parameters), `413` (file too large), `422` (invalid form values).

### `POST /api/v1/chat`

```json
{ "session_id": "test_user_001", "message": "How long is the internship?" }
```

Use the same `session_id` across requests to keep multi-turn context.

Response (`200`):

```json
{
  "session_id": "test_user_001",
  "answer": "The internship lasts three months.",
  "intent": "question",
  "sources": [
    {
      "document_id": "bc6138c6-f43b-458b-bfcc-e6231de343ce",
      "filename": "hr_rag_demo_documents.pdf",
      "chunk_index": 3,
      "score": 0.8123,
      "text": "..."
    }
  ],
  "booking_id": null
}
```

`intent` is one of `question`, `booking` or `cancel_booking`. A booking request returns, for example:

```json
{
  "session_id": "test_user_001",
  "answer": "Your interview is booked, Susan Aryal. Date: 2026-11-18, time: 11:00, email: susan@example.com. Confirmation ID: 1.",
  "intent": "booking",
  "sources": [],
  "booking_id": 1
}
```

Errors: `422` (invalid body), `502` (LLM provider failure or missing API key).

### `GET /api/v1/bookings`

Returns every stored booking (`id`, `session_id`, `name`, `email`, `interview_date`, `interview_time`, `created_at`).

## How it works

### Document ingestion

1. **Validate** the extension (`.pdf` or `.txt`) and size.
2. **Extract text**: UTF-8 decoding for text files, `pypdf` page extraction for PDFs.
3. **Chunk** with the selected strategy:
   - `fixed`: a sliding character window of `chunk_size` with `chunk_overlap`. Fast and predictable.
   - `sentence`: splits on sentence and paragraph boundaries, packs whole sentences up to `chunk_size`, and carries trailing sentences (up to `chunk_overlap` characters) into the next chunk. Oversized sentences fall back to fixed windows. This keeps ideas intact, which usually helps retrieval quality.
4. **Embed** all chunks in one batch (normalized vectors).
5. **Store** vectors plus payload (`document_id`, `filename`, `chunk_index`, `strategy`, `text`) in Qdrant, in batches of 64.
6. **Save metadata** (filename, content type, size, strategy, chunk parameters, chunk count, timestamp) in SQL.

### Conversational RAG

Each `POST /chat` request runs these steps:

1. Load the session's recent history and any in-progress booking state from Redis.
2. **Route**: an LLM call in JSON mode classifies the intent (`question`, `booking`, `cancel_booking`) and extracts booking slots. Relative dates such as "next Monday" are resolved against today's date. Invalid JSON falls back safely to a normal question.
3. For a **question**:
   1. If there is history, rewrite the message as a standalone question.
   2. Embed it and run a cosine similarity search in Qdrant (`TOP_K` chunks).
   3. Build a prompt that instructs the model to answer only from the retrieved context, and generate the answer.
   4. Return the answer with the supporting source chunks.
4. Append the user message and answer to Redis history (trimmed to the last `CHAT_HISTORY_TURNS` turns, with a TTL).

This is a hand-written pipeline: there is no `RetrievalQAChain` and no LangChain dependency.

### Interview booking

Booking details can arrive in any order across any number of messages.

1. The router extracts whatever the user provided (`name`, `email`, `date`, `time`).
2. New values are merged into the session's saved booking state in Redis.
3. Code validates the merged state: name length, email format, a date that is valid and not in the past, and a valid `HH:MM` time. Invalid values are dropped and the user is told why.
4. If anything is missing or invalid, the assistant asks only for what is still needed.
5. When all four values are valid, the booking is saved to SQL, the Redis booking state is cleared, and a confirmation ID is returned.
6. Saying something like "never mind" cancels the booking in progress.

Example conversation:

```
User:      I would like to book an interview
Assistant: To book your interview, I still need your full name, email address, preferred date, preferred time.
User:      Susan Aryal, susan@example.com, next Monday at 2pm
Assistant: Your interview is booked, Susan Aryal. Date: ..., time: 14:00, email: susan@example.com. Confirmation ID: 2.
```

### Data stored where

| Data                      | Store                                  |
| ------------------------- | -------------------------------------- |
| Chunk text and embeddings | Qdrant                                 |
| Document metadata         | SQL (`documents` table)                |
| Interview bookings        | SQL (`bookings` table)                 |
| Chat history              | Redis list `chat:<session_id>:history` |
| In-progress booking slots | Redis key `chat:<session_id>:booking`  |

## Testing and code quality

Run all checks from the project root:

```bash
pytest -v
ruff check .
mypy app
```

The test suite (16 tests) needs no network access, API keys, Docker or model downloads. It overrides the FastAPI dependencies with:

- an in-memory SQLite database,
- `fakeredis` for Redis,
- a fake embedder and fake vector store,
- a scripted fake LLM.

Coverage includes:

- Chunking: size and overlap behavior, sentence carry-over, oversized sentences, and invalid parameters.
- Ingestion API: both strategies, unsupported extension, empty file, and invalid overlap.
- Chat API: grounded answers with sources, multi-turn follow-up rewriting, a multi-turn booking flow, invalid email handling, and booking cancellation.

Type checking uses `mypy --strict` with the Pydantic plugin.

## Design decisions

- **Layered structure**: routes handle HTTP, services hold logic, and schemas define contracts. Services never import FastAPI, so they are easy to test and reuse.
- **Dependency injection**: components are provided through `app/api/deps.py`, which lets tests swap in fakes without patching.
- **Router plus code validation**: the LLM interprets language (intent, relative dates), but code decides whether a booking is valid and complete. The model never writes to the database directly.
- **Redis for short-lived state**: chat history and half-finished bookings expire automatically and are shared across API workers.
- **Swappable parts**: the LLM client works with any OpenAI-compatible endpoint (Groq, OpenRouter, a local Ollama), and the SQL layer works with any SQLAlchemy URL.
- **Lazy model loading**: the embedding model loads on first use, which keeps startup and tests fast.
- **Blocking work off the event loop**: embedding and vector search run in worker threads inside the async chat handler.

## Known limitations

- Retrieval searches across all ingested documents; there is no per-document or per-user filtering.
- There is no authentication or rate limiting.
- Booking does not check for double-booked time slots or timezones; dates and times are stored as given.
- Relative dates are resolved against the server's current date.
- Scanned PDFs without a text layer cannot be read (no OCR).
- There is no endpoint to delete documents or their vectors.
- SQLite is the default.
- Free cloud tiers can suspend idle clusters; resume or recreate the cluster and re-ingest if that happens.

## Troubleshooting

| Problem                                 | Fix                                                                                      |
| --------------------------------------- | ---------------------------------------------------------------------------------------- |
| `502 GROQ_API_KEY is not configured`    | Set `GROQ_API_KEY` in `.env` and restart the server                                      |
| Qdrant `403` or `Unauthorized`          | Check `QDRANT_API_KEY`                                                                   |
| Qdrant timeout or connection error      | Use `https://` and include `:6333` in `QDRANT_URL`                                       |
| Redis SSL or connection reset error     | The database needs TLS; use `rediss://`                                                  |
| Redis connection refused on `rediss://` | The database does not use TLS; use `redis://`                                            |
| Redis authentication error              | Re-check the password and URL-encode special characters                                  |
| Vector size mismatch                    | After changing the embedding model, update `EMBEDDING_DIM` and delete the old collection |
| Groq `429` rate limit                   | Wait a minute or set `GROQ_MODEL=llama-3.1-8b-instant`                                   |
| Slow first request                      | The embedding model is downloading; this happens once                                    |
| `ModuleNotFoundError: app`              | Run commands from the project root, not from inside `app/`                               |
